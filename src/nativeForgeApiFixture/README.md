# Optional native Forge FFAPI + Moonlight source fixture

This source set is attached **only** by `withNativeForgeApiFixture=true`. It is nonshipping and
adds exactly two required identities to the established default 85-case population (87 total):

- `moonlightnativeforgegametests.nativeforgeinteractionpersistsmoonlightmapdata`
- `moonlightnativeforgegametests.nativeforgeresourcereloadregeneratesmoonlightdata`

Its required config is `better_compat_fixes.native_forge_api_fixture.mixins.json`. The narrow
`nativeforgeapifixture.mixin` package contains only four observational mixins. Bootstrap, payload,
witness state and tests are outside that prefix. The build/SDK/predicate integration has a separate
owner; the preceding five native profiles and their identities must remain unchanged.

## What must actually run

The first test drives `ServerPlayerGameMode.useItemOn` with a real Forge FakePlayer, actual filled
map and supported floor-mounted levers. Its callback is registered using the normal FFAPI public
API before initial server data loading. Original Forge handler HEAD/RETURN witnesses require one
complete native bridge surrounding one callback; no test calls an event invoker or bridge directly.
Two PASS operations must really toggle the world block and increment Moonlight's registered
CustomMapData. FAIL must propagate through the original Forge cancellation result without toggling
or mutating. Other position, hand and player controls still toggle their real levers without touching
the custom data. Real map save/load must construct an independent persisted payload and preserve
vanilla colors/scale/dimension. Removing the payload from an encoded copy must restore zero, not a
stale prior value. The tests never insert the payload into ExpandedMapData manually.

The second test requires both FFAPI Forge pack-discovery handlers to have completed naturally and
opens the real selected `fabric` pack's descriptor. A public FFAPI resource reload listener reads the
fixture probe and resolves `supplementaries:tags/items/sign_posts.json` from the actual Moonlight
dynamic source, comparing its bytes with those read back after the original DynamicResourcePack
commit. Static Supplementaries tag existence alone cannot pass this witness. Startup and two
natural asynchronous server reloads must each deliver the listener and actually regenerate exactly
one matching generation. Resolved content must contain oak/spruce entries, and the real resulting
item-tag registry must bind the expected item.

Moonlight deliberately frees nonstatic generated resources after reload. The witness therefore
resolves generated bytes **during** the real FFAPI listener, before legitimate cleanup, and checks
the captured generation plus bound registry consumers after completion. It never disables cleanup,
marks resources persistent, or substitutes resources. Stable byte content between generations is
valid; a new original commit and new original listener delivery are still mandatory.

MinecraftServer.reloadResources internally managedBlocks when called on the server thread. The
test invokes that supported API from Minecraft's background executor, allowing it to schedule its
own server work, and polls the composed future from GameTest ticks. `join` is used only after
`isDone`, never to wait on a pending operation. No extra executor/thread is retained.

Both tests evaluate the real production supported-provider predicate against actual ModList and
also assert that global `isLoaded("fabric_api")` remains true. Predicate identity, native bridges,
map persistence and resource generation are complementary requirements, not interchangeable proofs.

## Evidence boundary

Standalone javac against the exact mapped SDK and existing mapped Forge classpath checks source
and ABI only. It does not prove Mixin application, Forge lifecycle discovery, callback delivery,
reload ordering, gameplay behavior, or the no-error audit. Actual sixth-profile compilation/native
execution and fresh same-candidate Dist remain required. This fixture supports only the selected
server paths; it is not upstream endorsement, all-FFAPI/all-Fabric support or a client rendering
verdict. Client behavior still requires the coordinated full Dist coverage.
